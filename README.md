# Can You Make It Sound Like You? Post-Editing LLM-Generated Text for Personal Style

**Team:** Fourth Dimension\
**Team Members:** Rahul Behra, Kashvi Patil, Soumili Basu

## Overview

This project is based on the research paper *"Can You Make It Sound Like
You? Post-Editing LLM-Generated Text for Personal Style"* by Connor
Baumler, Calvin Bao, Huy Nghiem, Xinchen Yang, Marine Carpuat, and Hal
Daumé III (University of Maryland).

The paper investigates whether people can edit text generated by a large
language model (LLM) so that it better reflects their own writing style,
especially in personal writing tasks such as wedding vows, apology
letters, and condolence messages.

## Problem Statement

LLM-generated writing can be fluent and useful, but it may sound generic
or fail to reflect an individual writer's voice. The study examines
whether human post-editing can make AI-generated drafts feel more
personal and stylistically authentic.

## Objectives

-   Study how post-editing changes the stylistic similarity of
    AI-generated writing to a person's unassisted writing.
-   Examine whether post-edited text retains detectable stylistic
    characteristics associated with LLM output.
-   Compare automatic style measurements with participants' perceptions
    of authenticity.
-   Understand participants' willingness to use post-editing for
    personal writing.

## Study Methodology

The paper reports a pre-registered online study involving **81
participants** in the final analysis.

Participants completed writing tasks under two conditions:

1.  **Control condition:** Participants wrote text themselves using
    their planned details.
2.  **Treatment condition:** Participants received an LLM-generated
    draft based on their planned details and then edited the draft to
    better match their personal style.

The researchers measured stylistic similarity using **LUAR text
embeddings** and also examined AI-detector scores from **PANGRAM**.
Participants reported how authentic and usable they found their writing.

## Key Findings

-   Post-editing made the resulting text stylistically more similar to
    participants' own unassisted writing.
-   Post-editing reduced stylistic similarity to the original
    LLM-generated text.
-   Even after editing, the text remained stylistically closer to
    LLM-generated writing than to participants' fully human-written
    control text.
-   Post-edited writing was more stylistically diverse than raw LLM
    output, but less diverse than unassisted human writing.
-   Participants often felt that their edited text represented their
    personal style, even when automatic measurements detected remaining
    LLM-style patterns.
-   A majority of participants preferred the post-editing workflow for
    future personal writing tasks. The paper reports that 58
    participants preferred post-editing, 20 preferred writing without
    AI, and 3 preferred using model-generated text without editing.
-   Participants identified the lack of originality in AI-generated
    drafts as an important obstacle to adoption.

## Conclusion

The study suggests that people can meaningfully personalize
LLM-generated drafts through post-editing, but editing does not
necessarily remove all stylistic traces of AI generation. It also
highlights a difference between automatic style measurements and
people's own judgments of whether a text sounds like them.

## Limitations

The paper notes several limitations:

-   Style was measured primarily with computational models, which may
    not capture every aspect of personal style.
-   Participants used simulated writing scenarios and were instructed
    not to include real identifying details.
-   The study focused on particular writing tasks and one post-editing
    workflow.
-   The study did not directly evaluate how the eventual recipients of
    the writing would perceive the edited text.

## Reproduction Pipeline and Analysis

This repository reproduces the paper's pre-registered hypotheses on the
released study logs and adds one novel analysis. The full pipeline runs
from the repository root with the Python environment in `.venv`.

### Data

- `data/raw/` — one JSON file per participant (81 participants). Each
  task stores the planned `details`, the LLM `model_generation`, the
  participant's `final_version`, a keystroke-level `edits` log, and
  `likert` self-ratings.
- `data/processed/` — derived files produced by the scripts below
  (task records, LUAR embeddings, similarity tables, analysis outputs).

### Stage 1 — build the analysis data

```bash
python src/load_dataset.py        # data/raw/*.json  -> task_records.jsonl (+ report)
python src/build_participant_data.py
python src/prepare_analysis.py     # -> analysis_ready.jsonl
python src/embed_luar.py           # LUAR-MUD embeddings -> luar_embeddings.npz (+ index)
```

`src/embed_luar.py` requires `torch` and `transformers` and downloads the
`rrivera1849/LUAR-MUD` model; the other stages need only numpy/pandas.
The embeddings are already committed, so the analysis stages below run
without re-embedding.

### Stage 2 — all hypotheses (one file)

```bash
python src/analysis/analyze_hypotheses.py
```

This single script reproduces **H1a** (also available standalone in
`src/analysis/analyze_h1a.py`) and adds **H1a', H1b, H1c, H2a, H2b, H2c,
and H3**. Every stylistic-similarity hypothesis uses cosine similarity of
LUAR-MUD embeddings; each is tested with a 10,000-sample permutation test
and Hedges' *g* with a bootstrap 95% CI, matching the paper and the
existing `analyze_h1a.py`. H3 reports the correlation between perceived
and measured self-similarity.

Outputs (in `data/processed/hypotheses/`):

- `all_hypotheses_summary.csv` — one row per hypothesis with the mean
  difference, permutation *p*, Hedges' *g* and CI, and the paper's
  reported *g* for side-by-side comparison.
- `h1_task_scores.csv` — per-task similarity scores used by H1 and by the
  novel analysis.
- `h2_homogeneity_pairs.csv` — between-author pairwise similarities
  (H2a/H2b/H2c).
- `h3_perception_vs_measure.csv` — perceived vs. measured self-similarity.
- `hypotheses_report.json` — machine-readable summary plus method caveats.

All seven H1/H2 effect-size **directions** reproduce the paper, and
several magnitudes are close:

- **H1b** *g* = −0.42 vs −0.41 (near-exact).
- **H2a** *g* = 1.54 vs 1.42, **H2b** −0.39 vs −0.69, **H2c** 1.82 vs 1.14
  — homogeneity uses the paper's between-author pairwise similarity on the
  **individual** texts (not participant centroids).
- **H3** uses **repeated-measures correlation** over both the draft and
  the edited text of each treatment task (Bakdash & Marusich, 2017), as the
  paper does: *r* = 0.23, 95% CI [0.15, 0.31] vs the paper's 0.244 ± 0.076.

The remaining gaps (**H1a** 0.40 vs 0.55, **H1c** −1.96 vs −1.43) trace to
the LUAR embedding step, which `src/embed_luar.py` flags as not an exact
reproduction of the authors' preprocessing (combined control reference and
a practical chunking strategy). Closing them requires re-embedding; the
analysis code itself matches the paper's method.

### Stage 3 — novel analysis: which edits recover personal style?

The paper shows *that* post-editing moves text toward the author's style;
it does not ask *which* editing behaviours do so. These two scripts test
that:

```bash
python src/novel/extract_edit_features.py   # edits -> interpretable features
python src/novel/analyze_edit_recovery.py   # features -> predict style recovery
```

- `extract_edit_features.py` turns each task's keystroke log and a
  draft-vs-final diff into 42 interpretable features (edit counts, timing
  and pauses, words/sentences changed, punctuation, contractions,
  first-person voice, lexical diversity). Output:
  `data/processed/novel/edit_features.csv`.
- `analyze_edit_recovery.py` predicts `change_after_editing` (the H1a
  movement toward the author's own style) from those features under
  participant-grouped cross-validation, comparing a *quantity* model
  (how much was edited) against a *kind* model (what kind of edit), with
  scenario and draft length as controls. Outputs:
  `feature_target_correlations.csv`, `model_comparison.csv`,
  `feature_importance.csv`, `novel_report.json`.

**Finding:** editing features explain a meaningful share of style recovery
(grouped-CV R² ≈ 0.27), and the *kind*-of-edit model generalizes better
than the raw *quantity* model. The strongest predictors are how
extensively the draft was rewritten (fraction of words changed,
characters inserted) together with word-level replacement.

## Project Scope

This repository reproduces the paper's reported study on the released
logs and adds one novel analysis (Stage 3). It is a course
reproduction: method choices that deviate from the authors' exact
procedure are documented in the scripts and in each run's
`*_report.json` caveats.
